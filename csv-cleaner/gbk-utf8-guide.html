CSV 文件打开全是乱码？GBK 和 UTF-8 的一场官司，10 分钟搞懂加解决

从 Excel 到 Python 到在线工具，一篇讲透编码问题的来龙去脉和三种场景的解法。

乱码的根源：同一串字节，两本字典

计算机存的本质是数字，文字要显示，需要一本"数字→文字"的对照字典（编码表）。

GBK：中文世界的老字典，收录了汉字和符号，一个汉字通常占 2 字节。

UTF-8：国际通用新字典，汉字占 3 字节，兼容全球所有文字。

乱码的本质：文件按字典 A 写入，你用字典 B 打开——同样的字节，查出来的字完全不同。用 UTF-8 的字典读 GBK 文件，"数据"两个字就会显示成"鏁版嵁"这种天书。

判断：你的文件是哪种编码

三个线索按可靠度排序：

1. 问出处：国内老系统、Excel 中文版"另存为 CSV"→ 大概率 GBK；新系统、网页导出、Mac/Linux → 大概率 UTF-8

2. 看乱码形态："鏁版嵁"类汉字 → GBK 被当 UTF-8 读了；"æ•°æ®"类西文 → UTF-8 被当 GBK 读了

3. 试验：不确定就用能切换编码的工具各试一次，10 秒钟的事

解决：分三种场景

场景一：Excel 打开乱码（最常见）

方法 A（不改动文件）：新建空白 Excel → 数据 → 从文本/CSV 导入 → 选文件时在"文件原始格式"里选编码
方法 B：用记事本打开 CSV → 另存为 → 编码选 UTF-8（带 BOM 更稳）→ 再用 Excel 打开

场景二：程序里读乱码

Python: pd.read_csv('file.csv', encoding='gbk')
Python: open('file.csv', encoding='utf-8')

场景三：在工具之间传来传去总乱码

把团队约定统一成一种——新文件一律 UTF-8，存量 GBK 文件用工具批量转换一次，一劳永逸。
