Markdown 粘贴到公众号/知乎排版全乱？3 个原因和对应解法

本地编辑器里层次分明的一篇 Markdown，粘进公众号标题变正文、代码块散架、列表消失。不是你写错了，是两边对"格式"的理解根本不同。这篇讲清 3 个原因和对应的 3 种解法。

先看清现象：乱的是哪几样

粘贴后最常见的四种翻车：

1. # ## 原样出现——标题没变成标题，就是带井号的普通文字

2. **加粗** 连星号一起显示——粗体语法没被解析

3. 列表的短横线还在，但缩进和圆点消失

4. 代码块失去底色和等宽字体，散成一段普通文字

原因一：平台编辑器不认 Markdown，只认富文本

Markdown 是「纯文本 + 记号」：## 标题 本质是三个字符，不是格式。你的本地编辑器（Typora、VS Code、Obsidian）会实时渲染这些记号，所以看着是排版好的。

但公众号、知乎、头条的编辑器收到的是一段纯文本——记号还在，格式信息从来就不存在。它们只认富文本（带格式的 HTML），不认记号。

这就是根因：不是复制粘贴坏了，是两边说的不是同一种语言。

原因二：各平台的"标签白名单"不一样

就算你把 Markdown 先转成 HTML 再粘贴，各平台还会按自己的白名单过滤：

· 公众号：过滤大部分外部样式和脚本，部分标签会被剥掉属性

· 知乎：对表格、代码块的支持有限制，复杂结构可能被简化

· 头条号：换行和空行容易被合并或吞掉

同一份 HTML，三个平台出来三个样——所以"一份 HTML 走天下"也不稳。

原因三：换行规则差异

Markdown 里「空行 = 分段」「行尾两个空格 = 强制换行」，而公众号习惯每行一个 <p>，头条对连续空行敏感。直接粘贴时这些差异全暴露。

解法一：手动重排（适合偶尔发一篇）

在平台编辑器里照着 Markdown 源码手动设置标题、加粗、列表。

优点：零依赖，当场解决

缺点：一篇 10 分钟起；三个平台要排三遍

适合：发文频率低、篇幅短

解法二：先转 HTML 再粘贴（适合愿意折腾的）

用任意 Markdown 编辑器的「导出/预览 HTML」功能，复制渲染结果（富文本）粘到平台。

1. Markdown 编辑器打开 → 预览模式
2. 全选预览内容复制（这时复制到的是富文本）
3. 粘贴到平台编辑器

优点：比手动快；保留大部分结构

缺点：平台白名单还是会吞样式；代码块、表格仍需逐个检查

解法三：按平台规则一键转换（适合一稿多发）

用会「分平台适配」的转换工具：同一份 Markdown，按头条/知乎/公众号各自的规则分别生成——头条自动短段落，知乎结论前置，公众号加阅读时长和行动清单。

优点：一次粘贴到位；一稿多发时省的时间最多

缺点：依赖工具的平台规则更新

→ 打开 Markdown 平台转换器（免费 · 纯本地 · 头条/知乎/公众号三平台适配 · 内容不出浏览器）
一个进阶技巧：别在平台编辑器里"从零排版"。正确的工作流是先写好 Markdown 母稿存本地，发布时按平台各生成一份——母稿是你的资产，平台编辑器只是出口。这样三个平台的内容永远一致，改稿也只改一处。
